# Migrating from DevClaw

Claw Foundry starts at 0.1.0 under `@essex75/claw-foundry`. Never run both plugins against one workspace. Migration is an explicit offline operation, not a startup side effect.

1. Stop the OpenClaw gateway and every worker, CLI, and other writer. Resolve uncertain worker deliveries where possible; retain unresolved markers if their outcome is unknown. Back up each entire workspace and `openclaw.json`, including session resources, before proceeding.
2. From this checkout, preview each workspace: `node scripts/migrate-devclaw-state.mjs <absolute-workspace>`. Then repeat with `--apply`. The script renames the entire `devclaw` directory to `claw-foundry` without rewriting file contents. It refuses an existing destination, links, missing sources and inaccessible resources. Do not run concurrent migration or setup. If both directories exist, stop and reconcile from the backup; never merge them blindly.
3. Install this checkout with `openclaw plugins install -l <absolute-checkout>` until the npm package is published. Disable/remove the old plugin installation. In `openclaw.json`, move `plugins.entries.devclaw` to `plugins.entries["claw-foundry"]`, preserving its complete configuration. Replace the plugin ID in `plugins.allow`, `plugins.deny`, plugin install records, and plugin-level tool allow/deny entries where present. Update the install source/package to `@essex75/claw-foundry` and its actual install path. If a new entry already exists, reconcile explicitly before saving; do not overwrite either configuration. Keep unrelated plugins and credentials intact.
4. Keep existing agent IDs, project slugs, worker session keys, bindings, operation IDs, timestamps and runtime records unchanged. Configured agent identity is independent of plugin identity; do not rename an existing `devclaw` agent or its session directories. The fallback agent ID for new installations is `claw-foundry`. Update custom scripts and environment variable names from `DEVCLAW_*` to `CLAW_FOUNDRY_*` where used. Update explicit old storage paths in custom prompts, automation and scoped permission rules. Neutral tool names such as `task_start` and `work_finish` stay unchanged.
5. Review workspace `AGENTS.md`, `TOOLS.md`, `HEARTBEAT.md`, identity files and custom role prompts. Replace old CLI invocations with `openclaw claw-foundry ...` and paths with `claw-foundry/...`, preserving custom instructions. Setup is create-only and does not rewrite these files automatically. Do not run a default reset over customized files.
6. Compare migrated files against the backup byte for byte, especially `projects.json`, all active/archive/creation issue stores, attachment indexes/bytes, delivery resolution records and audit journals. Verify project and worker counts, issue identities, reservations and recovery markers before resuming scheduling. Run `openclaw claw-foundry doctor --workspace <absolute-workspace>` and inspect each registered project. Never initialize missing issue records from provider labels.
7. Restart the gateway, inspect plugin registration and logs, then verify existing tasks and worker recovery before creating new work. Original provider issue metadata/creation markers remain `devclaw:issue-metadata` and `devclaw:issue-creation`; gateway replay keys retain `devclaw-`. These are persisted protocol identifiers, not branding. Do not replace them in issue bodies or saved records. Existing attachment URLs remain valid; new GitHub attachment uploads use `claw-foundry-attachments`.

State paths, configuration loading and setup refuse any workspace still containing a `devclaw` entry, even if `claw-foundry` also exists. No empty replacement store is created. Diagnostic logging reports the migration requirement without writing a second journal.

Rollback: stop every writer, restore the full workspace and OpenClaw configuration from the matching backup, and reinstall the previous plugin. Do not copy only the registry or run the old plugin against newly modified state.

The original repository, Git history, authors and dates are unchanged. See [upstream history](../CHANGELOG.devclaw.md), [LICENSE](../LICENSE) and [publishing](../PUBLISHING.md).
